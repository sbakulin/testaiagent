# Шаблон агента для платформы Galdria

Один репозиторий — один агент. Скопируйте эти файлы в свой репозиторий и замените тело `handler` в `service.py`.

## Что должно быть в репозитории

- `Dockerfile` в корне.
- Сервис слушает порт из переменной `PORT` (платформа задаёт `8080`): `GET /healthz` и `POST /agui`.
  Всё это уже делает `uai_agent_kit.py` — менять его не нужно.

## Что даёт платформа

При добавлении агента платформа сама выпускает ему ключ модели с лимитом и ключ маскирования и передаёт их
контейнеру переменными окружения. В коде и в репозитории ключей нет. К модели агент ходит только через шлюз
маскирования (`gateway_completion()` из обвязки). Запустить агента можно только через платформу: из её чата,
по личному токену или по токену приложения из карточки агента.

## Что пишет автор

Одну функцию `handler(run)`:

- `run.task` — текст задачи; `run.state` — состояние из прошлого сообщения; `run.params` — параметры запуска;
- `run.text("…")` — сообщение в чат;
- `run.tool_start(id, имя, аргументы)` и `run.tool_result(id, результат)` — шаг работы: начат и закончен;
- `run.set_state({...})` — промежуточный или итоговый результат для интерфейса;
- `run.check_cancelled()` — прекратить работу, если пользователь нажал «Остановить».

## Запуск у себя

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
UAI_AGENT_TOKENS=localdev PORT=8931 .venv/bin/python service.py
```

## Добавить на платформу

Страница Agents → «Add from repository»: имя, адрес репозитория, ветка, токен чтения (для закрытого репозитория).
После изменений в репозитории — кнопка обновления; если новая версия не собралась или не отвечает, работает прежняя.
